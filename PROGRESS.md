## Sprint 2 — Matcher Agent
Status: **complete** (4 of 4 deliverables; gate met).

Built the CV-to-job matching pipeline end-to-end. `models/profile.py` defines a strict-subset `Profile` (LLM cannot output skills absent from the PDF source text — enforced post-parse) with a deliberately `full_name`-free `to_embedding_text()` so names cannot bias semantic similarity. `tools/cv_parser.py` parses PDFs via `pypdf` and an LLM JSON pass guarded by `JSON_ONLY_PREAMBLE` (added to `BaseAgent` as a Sprint-2 enabling change). `tools/embedder.py` wraps the GWDG `multilingual-e5-large-instruct` endpoint at `EMBED_DIM = 1024`; calibrated the input truncation against a real German CV that breached the 512-token model limit at 300 words — added a two-axis cap (`MAX_INPUT_WORDS = 300`, `MAX_INPUT_CHARS = 1800`) since German compound nouns push the tokens-per-word ratio above 1.8. `agents/matcher_agent.py` orchestrates the two-stage ranking: pgvector cosine via the `match_jobs_for_profile` RPC narrows hundreds of jobs to top-N candidates cheaply, then the LLM gap analysis populates `matched_skills`, `gaps`, and `rationale` only for the survivors — spending LLM tokens where they actually matter. The schema gained four Sprint-2 migrations: `003_resize_embeddings.sql` (1536→1024 dim fix for GWDG), `004_profile_languages.sql`, `005_match_jobs_rpc.sql`, `006_add_matched_skills_to_match_scores.sql`. Shipped `scripts/seed_demo_fixture.py` (records the (prompt, response) pairs from a real GWDG run) and a deterministic regression test (`test_matcher_against_demo_fixture`) that replays them — a peer reviewer can clone the repo and reproduce the slide Top-N without needing GWDG or Supabase access. `scripts/demo_match.py` is the four-phase live closer (Scout → Embed → Match → Print) used in the Sprint 2 presentation. Also fixed pre-existing Sprint 1 lint/type drift (UP017, UP037, generic-`dict` returns) and backfilled three missing Sprint 1 test files. Final state: ruff clean, mypy clean (22 source files), pytest **114 passed**, 0 live calls in tests.

## Sprint 3 — Writer Agent
Status: **complete** (4 of 4 deliverables; gate met).

Implemented the document-generation vertical end-to-end. `tools/cover_letter_template.py` wraps a Jinja2 rendering pipeline with two locale variants (`cover_letter.jinja2` for English, `cover_letter_de.jinja2` for German); a small LLM call populates the per-job fields while keeping all text grounded in the `Profile` strict-subset guard from Sprint 2. `tools/cv_variant.py` populates `highlighted_skills` on the `Profile` — a strict subset of `profile.skills` filtered to those appearing in `match.matched_skills` (case-insensitive, original casing preserved); `tools/docx_exporter.py` then writes the `.docx` CV variant with the highlighted skills surfaced. `tools/docx_exporter.py` writes python-docx `.docx` artefacts for both documents. `agents/writer_agent.py` orchestrates the end-to-end flow: retrieve match, build cover letter, build CV variant, export both to `ARTIFACTS_DIR`, upsert the application row to `ready_to_send`. `models/cover_letter.py` is the Pydantic output schema with strict validation. The schema gained two migrations: `007_add_ready_to_send_status.sql` (new `ready_to_send` constraint in `applications.status`) and `008_applications_job_id_unique.sql` (unique constraint per job, needed for Writer's upsert). Scout gained multi-source routing so JSearch/RapidAPI can supplement Arbeitsagentur; `models/profile.py` gained a `full_name` field (used in the cover letter salutation). Final state: ruff clean, mypy clean, pytest **242 passed**, 0 live calls in tests.

## Sprint 4 — Tracker Agent + Streamlit UI
Status: **complete** (3 of 3 deliverables; gate met).

Completed the application-lifecycle loop. `agents/tracker_agent.py` owns all legal state transitions (`new → ready_to_send → applied → interview → offer / rejected`) and enforces the state machine strictly — invalid transitions raise `InvalidTransitionError` (a `ValueError` subclass defined in `agents/tracker_agent.py`). `delete_my_data()` returns a `DeleteSummary` and implements GDPR right-to-erasure by wiping the `profile`, `match_scores`, and `applications` tables (via an impossible-sentinel-UUID `DELETE` that satisfies Supabase's required-filter rule) and unlinking every generated `.docx` artefact from disk. `migration 009_add_full_name_to_profile.sql` makes the `full_name` column nullable for schema compatibility. `ui/app.py` is a Streamlit dashboard with three pages: Jobs (live fetch + filter), Matches (score threshold slider, quick-apply button), and Applications (status board with inline state-transition buttons and the delete-my-data sidebar action). The UI talks directly to Supabase via the existing client; no live LLM calls happen in the UI layer. End-to-end integration is exercised through the Streamlit dashboard (Scout → Matcher → Writer → Tracker). Final state: ruff clean, mypy clean, pytest **242 passed**, 0 live calls in tests.
